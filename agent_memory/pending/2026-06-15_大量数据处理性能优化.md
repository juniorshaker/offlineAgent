# 大量数据处理性能优化

**创建时间**: 2026-06-15
**状态**: 待处理
**优先级**: 中

## 问题

处理大量数据（如 45+ 个 SQL 文件）时，上下文迅速膨胀导致超时/处理不了。

## 根因分析

1. **工具结果全量回注**：`read_file` 截断点 50000 字符（≈12K tokens），10 个文件 = 120K tokens
2. **`find_files` 无结构化**：返回全路径 + 文件大小，无分组
3. **全文盲注**：SQL 文件含注释、空白、模板代码，有效逻辑只占 20%
4. **旧轮次不压缩**：context_compressor 触发阈值 70%，SQL 场景膨胀速度 > 压缩速度

## 方案

### B 方案（推荐先上）：分批 + 渐进式处理
- 在 system prompt 注入"大量文件处理范式"
- 先建索引 → 逐批深度分析 → 每批完成后 LLM 自行摘要 → 只保留摘要进下一批
- 不改代码，改 prompt，零风险

### A 方案：工具结果智能摘要
- `read_file` 加 `mode="summary"` 参数
- SQL/代码文件先提取结构（表名、存储过程名、函数签名），正文按需再读
- 上下文消耗降低 60-70%

### C 方案：工具结果后处理层
- tool_executor 加一层，根据大小/类型自动压缩
- 如 SQL 文件只保留 CREATE/INSERT/SELECT 核心语句
- 对 LLM 透明，全局生效

## 建议

B + A 组合：B 先上改 prompt 看效果，A 跟上做工具层优化。
