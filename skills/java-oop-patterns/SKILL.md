# Java 面向对象与设计模式识别

## Overview

解析代码 OOP 设计，分析继承、接口实现、多态、方法重写与重载核心逻辑。自动识别单例、工厂、策略、观察者、装饰器等常见二十余种设计模式。评估类结构设计合理性、封装性，指出设计缺陷并给出优化思路。

## Analysis Checklist

### 1. 类结构分析
- 继承层次：绘制类继承树，标注每个类的角色（基类/抽象类/具体类）
- 接口实现：列出实现的接口及每个接口方法的实现位置
- 抽象类与具体类的区分：分析模板方法模式是否存在
- 组合 vs 继承：分析是否应该用组合替代继承

### 2. 多态与重写/重载
- 列出所有 @Override 方法，验证是否正确覆盖
- 列出所有重载方法，分析参数类型和数量的差异
- 检测重载歧义：调用时编译器无法确定绑定哪个方法
- 分析多态调用点：父类引用调用子类实现的位置

### 3. 封装性评估
- 字段访问权限合理性：是否该用 private 但用了 public
- 内部类使用：静态内部类 vs 非静态内部类 vs 匿名内部类 vs Lambda
- getter/setter 的合理性：是否暴露了不该暴露的内部状态
- 可变对象的防御性拷贝
- 包级别的封装：是否有跨包访问的内部实现细节

### 4. 设计模式识别（覆盖 20+ 模式）
创建型：单例（含双重校验锁/枚举单例/静态内部类）、工厂方法、抽象工厂、建造者、原型
结构型：适配器、桥接、组合、装饰器、外观、享元、代理（静态/动态/CGLIB）
行为型：责任链、命令、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者
- 对每个识别的模式说明：模式名称、应用场景、参与类、优点和风险

### 5. SOLID 原则评估
- 单一职责：类是否承担了过多不相关的职责
- 开闭原则：是否通过继承/接口扩展而非修改源码
- 里氏替换：子类是否能完全替换父类
- 接口隔离：接口是否过于臃肿，是否存在空实现方法
- 依赖倒置：是否依赖接口而非具体实现

### 6. 设计缺陷识别
- 上帝类/万能类：超过 500 行或 20 个 public 方法
- 霰弹式修改：修改一个功能需要改动多个类
- 功能依恋：方法过度使用其他类的数据
- 拒绝的遗赠：子类不使用的父类方法
- 数据泥团：总是同时出现的字段组合应抽离为新类

## Common Pitfalls

- 不要把简单的 getter/setter 当成违反封装
- 不要把只有一个实现类的接口当成过度设计（可能为将来扩展预留）
- 不要把 Spring 的依赖注入当场违反依赖倒置
- 设计模式的识别要基于意图而非仅基于结构相似
- 简单工厂和工厂方法容易混淆：看是否有多态创建
